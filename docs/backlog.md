## Current operating limits

- No paid campaign, custom domain, payment system, native app, or always-on server during the web validation phase.
- No visible login before value; every request still has a server-derived guest or registered principal.
- One scale-to-zero backend with server-side credentials, quotas, authorization, idempotency, and kill switches.
- At most six model calls, twelve tool calls, one escalation, 40,000 input tokens, and 4,000 output tokens per interactive run.
- Search broadly, fetch details for a shortlist, and route finalists only.
- Precise trip data stays out of Git, URLs, logs, and analytics.

Documentation completion is not product or market validation.

## Firestore stores: what the fake does not prove

The Firestore adapters are tested only against `backend/app/stores/fake_firestore.py`, an in-process fake of the small client surface they use. The fake proves our adapters' logic, transaction shape (reads before writes, retry on conflict), value types and document contents. It does NOT prove real Firestore behaviour: composite or missing indexes (the adapters use only automatic single-field indexes, which is unverified), TTL policy timing (the real service deletes expired documents late, so every adapter also checks expiry on read), contention and the one-write-per-second-per-document limit (the spend counter is one hot document), transaction lock waits and retry limits, latency, security rules, or quotas.

TODO before pilot traffic (all need owner approval to create cloud resources, decision 26):

- DONE (2026-10-26): the contract suites (stores, actions, account, history, saved places, workspace CAS) have a third `emulator` parametrisation using the real `google-cloud-firestore` client (`backend/tests/fs_backend.py`; skipped unless `FIRESTORE_EMULATOR_HOST` is set) and CI job `firestore-emulator` runs them against a digest-pinned `google-cloud-cli` emulators image. Verified locally against that image: 174 passed, 14 skipped (the skips are the hot-contention tests, below). Findings:
  - **No adapter bug found.** Every query, transaction shape (reads before writes), value type and document the adapters use works on the real client; no composite index was demanded (but the emulator never demands one, so the index question stays open until a real database runs the queries).
  - **Hot-document contention is far worse than the fake shows.** Concurrent read-modify-write transactions on ONE document serialise slowly: 2 writers took about 2 s, 3 about 4 s, 8 writers on one quota document took over a minute and exhausted the 30-attempt budget (`Failed to commit transaction in 30 attempts`), where the fake finishes instantly. No overspend or lost update occurred (a failed transaction changes nothing), but a real burst on `cost_totals/pilot`, a per-principal quota document or a workspace head would stall or error. The 14 many-thread tests are marked `hot_contention` and skipped on the emulator; `test_emulator_behaviour.py` keeps a 2- and 3-writer race. Still TODO: load-test the real service and shard or batch the hot counters; decide what a contention failure should return to the client (today the `ValueError` is an untyped 500).
  - **The emulator does not enforce TTL** (the fake's `run_ttl_sweep` has no real counterpart); TTL deletion timing remains unverified, and the scheduled purge (`POST /internal/purge`) is the early, tested backstop. The sweep query (`expires_at <= now` plus `limit`) runs on the emulator.
  - The emulator accepts anonymous credentials and a throwaway project per test (cleared after each test); security rules and IAM are not exercised.

## Review follow-ups (2026-10-26 security review)

Not fixed in the review pass; each needs a contract change or owner input.

- **Saved-place DELETE carries the place ID in the query string** (`DELETE /v1/saved-places?place_id=`): query strings reach proxies and request logs. The container now runs uvicorn with `--no-access-log`, but the real fix is an opaque path identifier (a contract change; regenerate the web client with it).
- **Backend dependency lockfile is missing.** `pyproject.toml` pins only the auth extras; the container installs whatever resolves at build time. Add a hash-pinned lockfile (for example `pip-compile --generate-hashes`) and install from it. The base image is pinned by digest (update both `FROM` lines together).
- **History tag provenance:** `OutingRecord.intent_tag` has no `source` field, so a tag derived from the user's own request (`derive_intent_tag`) cannot be marked as derived rather than chosen. Adding a `source` enum is an additive contract change; until then the derived tag stays as documented in decision 19 (conservative, never KIDS).
- **Consent ledger compaction:** the ledger stays append-only and bounded (decision 28); a destructive compaction of withdrawn pairs was deliberately not built.
- **Real Firebase Admin credentials** are still an owner TODO; until then `me:delete` reports `login_not_removed` (decision 28) and `can_delete` is false.
