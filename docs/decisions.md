2026-10-11: Chose explicit button activation for the first Android voice experience. The user presses and holds the in-app microphone button, releases to submit or cancels to discard; capture stops after 60 seconds and audio is discarded after transcription. The microphone is otherwise off. Wake words, continuous background capture, volume-key AccessibilityService and default-assistant replacement are deferred.

2026-10-11: Restricted the model product boundary to trip/outing discovery, planning, execution and recovery plus app help. A server-owned gate classifies travel, app-help, mixed, out-of-scope and safety requests before the planning model. Mixed requests keep only their travel span; out-of-scope requests receive a fixed response with no planning tools. Prompts, user text and retrieved content cannot expand the domain or tool allowlist.

2026-10-11: Added initial token safety ceilings: 2,000 tokens per user input; 12,000 compiled input and 1,200 output per planning call; 40,000 input and 4,000 output per agent run; six model calls, twelve tool calls and one escalation. Guest and registered-free internal daily caps are 60,000/6,000 and 120,000/12,000 input/output tokens. All provider-reported token categories enter the cost ledger. Truncated or malformed output cannot update state or execute an action.

2026-10-11: Adopted an anonymous-first, entirely free validation model. First use has no sign-up screen; Firebase Anonymous Authentication supplies the server-verifiable tenant identity. A guest receives 50 successful user turns or 10 activated trips over that identity's lifetime, whichever is first. The current response finishes, and the next metered action requests a free Google or email-link account. Registered free begins with 100 turns and 10 activated trips per rolling 30 days. The values are versioned hypotheses; there is no paid tier in the validation roadmap.

2026-10-11: Defined a successful user turn as one submission that receives a completed response and an activated trip as an accepted plan followed by save, reminder or Maps launch. Failures, retries and duplicate idempotency keys do not consume the public allowance. Provider attempts still enter a separate internal cost ledger. Viewing, Maps handoff, export and deletion remain available after exhaustion, and an in-progress trip is never interrupted.

2026-10-11: Guest state is local-first; the server keeps minimal structured active-workspace state for seven inactive days plus identity, quota, cost and idempotency records. Calendar, durable routines, cross-device sync and recurring server monitoring require a registered-free account and separate consent. Registration normally links the anonymous UID; credential collisions use an explicit resumable merge. No fingerprinting, implicit precise-history upload or silent merge is allowed.

2026-10-10: Replaced the planner-centered product definition with an agent-first travel decision system. Place search, routes, Calendar, weather, memory, reminders and deterministic solvers are tools. Solvers validate hard subproblems only when relevant; they do not define the product or require every user to specify a route.

The first pilot covers at least 30 vague, specific and recovery goals. Android remains the first intended product after evidence.

2026-10-10: Expanded the long-term product from a single departure optimizer into a persistent personal trip assistant for one-stop, calendar-derived, routine, multi-stop, and multi-day travel. 2026-10-10: Chose a direct hosted Gemini 3.5 Flash-Lite API behind a provider-neutral model gateway for the future conversational agent. Use OpenRouter for evaluation or restricted fallback, not the primary path; defer self-hosting until measured sustained inference economics or privacy requirements justify its GPU and operations burden. The model interprets and explains only. Deterministic tools own time arithmetic, feasibility, route estimates, stop sequencing, and side effects.

2026-10-10: Calendar, exact locations, routines, and OAuth tokens are sensitive. Continuous background location, permanent raw calendar/chat storage, autonomous booking/purchase, and silent routine inference are excluded.

2026-10-10: Added a provider-license boundary after security review. 2026-10-10: Replaced the fixed home-by form with a deterministic adaptive trip interview. The MVP supports fixed activity starts, latest destination-ready, activity-finish, destination-departure and home-arrival times, flexible windows, and intersections. The interface asks one high-coverage opening question, reuses every supplied fact, requests purpose only when it changes time semantics, and confirms one editable timeline before any route call. Correct hard constraints and feasibility take priority over question count. The initial parser is rule-based; any later language model can propose candidate slots only and cannot confirm constraints, choose questions, decide feasibility, or rank plans. Issue #12 owns the interview policy, gold dialogues, and independent minimum-safe-question evaluation.

2026-10-10: The adaptive-intake quality targets are zero missed or invented hard constraints in curated P0 cases, at least 99% correct confirmed requests in generated supported cases, deterministic termination with no repeated question, median question-count regret zero and p95 at most one question above an independent oracle. A typical saved-home request should need at most three median follow-ups; a fully specified request needs only location resolution and grouped confirmation. These are proposed gates, not measured performance.
